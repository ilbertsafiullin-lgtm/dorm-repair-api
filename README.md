# Сервис заявок на ремонт в общежитии — API на FastAPI

Учебный проект по дисциплине «Технологическая практика», задание № 2.
Выполнил: Сафиуллин И. И., группа 09-401.

## О проекте

API для подачи и просмотра заявок на ремонт в студенческом общежитии.
Студент оставляет заявку (например, «течёт кран»), а сотрудники видят все заявки в одном месте.

База данных пока не подключена: заявки хранятся в списке Python внутри `main.py`.
После перезапуска сервера добавленные заявки пропадают, и это ожидаемое поведение.

## Сущность «Заявка»

| Поле          | Тип    | Кто заполняет | Описание                                   |
|---------------|--------|---------------|--------------------------------------------|
| `id`          | int    | сервер        | Уникальный идентификатор                   |
| `title`       | str    | пользователь  | Краткое название проблемы (3–100 символов) |
| `description` | str    | пользователь  | Подробное описание (10–500 символов)       |
| `category`    | str    | пользователь  | Категория: plumbing, electricity и т. д. (3–30 символов) |
| `room`        | int    | пользователь  | Номер комнаты (1–9999)                     |
| `status`      | str    | сервер        | Статус; у новой заявки всегда `new`        |
| `created_at`  | str    | сервер        | Дата и время создания                      |

## Установка и запуск

```bash
# 1. Создать и активировать виртуальное окружение
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

# 2. Установить зависимости
pip install -r requirements.txt

# 3. Запустить сервер
fastapi dev main.py
```

Сервер будет доступен по адресу http://127.0.0.1:8000,
интерактивная документация Swagger откроется на http://127.0.0.1:8000/docs.

## Эндпоинты

| Метод | Путь                     | Описание                                   | Коды ответа |
|-------|--------------------------|--------------------------------------------|-------------|
| GET   | `/requests`              | Список заявок                              | 200, 422    |
| GET   | `/requests/{request_id}` | Одна заявка по id                          | 200, 404, 422 |
| POST  | `/requests`              | Создать заявку                             | 201, 422    |

### Параметры `GET /requests`

- `category` — необязательный фильтр по категории (без учёта регистра);
- `limit` — максимальное количество заявок в ответе (целое число от 1).

## Примеры запросов

Все заявки:
```
GET /requests
```

Только сантехника:
```
GET /requests?category=plumbing
```

Не больше двух заявок:
```
GET /requests?limit=2
```

Одна заявка (200):
```
GET /requests/1
```

Несуществующая заявка (404):
```
GET /requests/999
→ {"detail": "Заявка с id=999 не найдена"}
```

Создание заявки (201):
```
POST /requests
Content-Type: application/json

{
  "title": "Не горит лампа",
  "description": "В коридоре у комнаты не горит потолочная лампа",
  "category": "electricity",
  "room": 305
}
```

Ответ: созданная заявка, к которой сервер добавил `id`, `status: "new"` и `created_at`.

Некорректные данные (422): слишком короткое название, отсутствующее поле или текст вместо номера комнаты:
```json
{ "title": "ок", "description": "коротко", "category": "x", "room": "пятьсот" }
```

## HTTP-коды

| Код | Когда возвращается                                    |
|-----|-------------------------------------------------------|
| 200 | Успешное получение списка или одной заявки            |
| 201 | Заявка успешно создана                                |
| 404 | Заявка с указанным id не найдена                      |
| 422 | Переданы некорректные данные (не прошли валидацию)    |
